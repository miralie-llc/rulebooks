# Sources and design notes

Reviewed 7 November 2026. This register records sources informing the model and the findings to consider during implementation. Published rule records will carry their own exact source locators; this register is not evidence that a complete formalization already exists.

These are reference leads and design precedents, not automatically accepted content or a commitment to implement every system listed. Runtime/library comparisons, sporting examples and governance analogs inform terminology only. The [selected product plan](../product/README.md) defines scope; source selection and exact edition verification happen in content work.

| Source | Role and finding | Effect on RuleBooks |
|---|---|---|
| [BoardGameGeek XML API2](https://boardgamegeek.com/wiki/page/BGG_XML_API2) and [Chess960 catalog entry](https://boardgamegeek.com/boardgame/12608/chess960) | Catalog metadata. External IDs, alternate names, and linked game entries aid identification. The Chess960 entry distinguishes a named derivative with different setup. | Separate catalog identity and external links from a revision of formal behavior. Use FIDE for authoritative chess rules. |
| [Ludii Language Reference, §2.1](https://ludii.games/downloads/LudiiLanguageReference.pdf) and [Ludii User Guide, §3](https://ludii.games/downloads/LudiiUserGuide.pdf) | Formal-language precedent. A game description composes players, mode, equipment, and rules from structured ludemes. | Make formal rules inspectable trees and give reusable definitions stable IDs. A future Ludii exporter can map supported constructs. |
| [Stanford GGP game description](https://logic.stanford.edu/ggp/chapters/clean_slate.html) and [GDL specification](https://www.cs.uic.edu/~hinrichs/papers/love2006general.pdf) | Formal-language precedent. Rules define initial facts, legal actions, next facts, termination, and goals through shared relational vocabulary. | Start with explicit facts and derived definitions. Keep setup, legality, state updates, and outcomes distinct in the next semantic layer. |
| [GGP public repositories](https://games.ggp.org/) and [Stanford Gamemaster course](https://logic.stanford.edu/ggp/stanford/index.php) | Corpus precedent. Gamemaster game descriptions sit alongside other independently maintained GDL libraries. | Treat imported descriptions as identifiable artifacts with their own edition and provenance. Individual library rulesheets were outside this review. |
| [GDL-II paper](https://cdn.aaai.org/ojs/7647/7647-13-11177-1-2-20201228.pdf) | Formal-language precedent. The extension represents chance and what each player perceives. | Distinguish world state, chance, and player observations in future versions. |
| [OpenSpiel concepts](https://openspiel.readthedocs.io/en/latest/concepts.html) and [core API](https://openspiel.readthedocs.io/en/stable/api_reference.html) | Runtime contract. The API separates chance, simultaneous actions, legality, state transitions, player information, and returns. | Use these boundaries to test the model's generality. Treat OpenSpiel as an implementation target with a separate adapter. |
| [boardgame.io concepts](https://boardgame.io/documentation/) and [phases](https://boardgame.io/documentation/phases.html) | Open engine precedent. Global phases, turns, and player-specific stages can govern different action sets. | Leave room for phase and per-player stage semantics as the model grows. |
| [AlphaZero paper](https://doi.org/10.1126/science.aar6404) and [Assessing Game Balance with AlphaZero](https://arxiv.org/abs/2009.04374) | Downstream consumer and variant precedent. AlphaZero uses game rules for self-play. The variant study experiments with distinct changes to chess rules. | Keep learning machinery and policy encodings downstream. Model rule changes as explicit overrides of a pinned base. |
| [Wikipedia rules of chess](https://en.wikipedia.org/wiki/Rules_of_chess) | Secondary orientation. Organizes movement, special moves, outcomes, and competition procedure for human readers. | Use as a discovery aid. Anchor formal chess clauses to FIDE. |
| [FIDE Laws of Chess, effective 1 January 2023](https://handbook.fide.com/chapter/E012023) | Primary chess authority. §3.6 specifies knight movement. §3.8.2 distinguishes retained castling rights from temporary restrictions. §§9.2 and 9.6 distinguish claimable and automatic repetition draws. | Candidate source for the chess content task. Cite exact locators and distinguish position history, claims and automatic outcomes when the rules are collected and modeled. |
| [Magic Comprehensive Rules](https://magic.wizards.com/en/rules), [Magic Tournament Rules, §§1.7, 2.9, 3.3–3.6](https://media.wizards.com/ContentResources/WPN/MTG_MTR_2026_Feb27_EN.pdf), and [August 10, 2026 banned and restricted announcement](https://magic.wizards.com/en/news/announcements/banned-and-restricted-august-10-2026) | Governance precedent. Game rules, format eligibility, official card text, and event rulings have different scopes. | Record effective dates for format changes and cite the provision granting an official’s decision power. Keep a ruling and its finality scoped to the relevant proceeding. |
| [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12) | Serialization and validation specification. | Validate record shape with JSON Schema, then check references and semantic constraints separately. The current implementation validates work records and [publication contract 0.1.0](../architecture/publication-contract.md); executable language semantics remain planned. |

The register links to external sources and assigns no reuse terms to their content. Public formal encodings require their own source correspondence and review.
